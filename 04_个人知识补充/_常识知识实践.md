## 第一层：常识层

### 1.1 什么是算子？为什么需要它？

| 问题 | 通俗解释 |
|-----|---------|
| 什么是AI算子？ | AI模型中的"计算单元"，就像乐高积木块，模型由各种算子搭建而成 |
| 为什么需要算子？ | 模型需要大量计算，算子是执行这些计算的基本单元 |
| 算子和模型的关系？ | 模型 = 算子组合 + 参数，就像程序 = 函数调用 + 数据 |
| 算子有哪些类型？ | 逐元素运算（如ReLU）、归约运算（如sum）、矩阵运算（如matmul）等 |

### 1.2 为什么算子需要"开发"？

| 问题 | 通俗解释 |
|-----|---------|
| 算子不是现成的吗？ | PyTorch/TensorFlow提供了常用算子，但新模型、新硬件需要新算子 |
| 为什么不能直接用Python写？ | Python太慢，算子需要在GPU/NPU上高效运行，需要特殊编程 |
| 算子开发难在哪里？ | 需要理解硬件架构、并行计算、内存管理等底层知识 |

### 1.3 GPU/NPU是什么？为什么需要它们？

| 问题 | 通俗解释 |
|-----|---------|
| GPU和CPU有什么区别？ | CPU是"全能选手"，GPU是"并行专家"，能同时执行成千上万个简单任务 |
| NPU是什么？ | 专门为神经网络设计的处理器，比GPU更高效 |
| 为什么AI需要GPU/NPU？ | AI计算量大、可并行，GPU/NPU能大幅加速 |

### 1.4 这个技术栈能解决什么问题？

| 问题 | 通俗解释 |
|-----|---------|
| Triton是什么？ | 一种简化GPU编程的语言，比CUDA更容易写 |
| FlagGems是什么？ | 一个算子库，收集了很多现成的高效算子 |
| KernelGen是什么？ | 一个AI工具，能自动生成算子代码 |
| 三者什么关系？ | KernelGen生成代码 → Triton编写代码 → FlagGems收集代码 |

### 2.2 Triton核心技术

#### 2.2.1 原理与架构

| 问题 | 知识要点 |
|-----|---------|
| Triton如何简化GPU编程？ | 提供更高层抽象，自动处理线程管理和内存优化 |
| Triton编译器如何工作？ | Python DSL → TTIR → TTGIR → PTX/SPIR-V |
| Triton如何实现硬件无关？ | 通过后端抽象层，支持CUDA、ROCm、OpenAI等 |
| Triton与CUDA的本质区别？ | CUDA需要手动管理线程，Triton自动管理 |

#### 2.2.2 编程模型

| 概念 | 解释 | 对应硬件 |
|-----|------|---------|
| **kernel** | 在GPU上执行的函数 | 一个计算任务 |
| **block** | 一组线程的集合 | SM上的执行单元 |
| **grid** | 所有block的集合 | 整个GPU |
| **program_id** | 当前block的索引 | 用于定位数据 |

#### 2.2.3 核心问题清单 

**Q: Triton的编程模型（kernel、block、grid）如何映射到硬件执行？**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                     Triton 编程模型 → 硬件映射                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   Triton概念              硬件映射                执行模型                   │
│   ────────────────────────────────────────────────────────────────────────  │
│   Grid（网格）      →     整个GPU设备           多个SM并行执行               │
│   Block（块）       →     SM（流式多处理器）      一个SM执行一个block         │
│   Program           →     Block实例              SPMD执行模型               │
│   Warp              →     32个线程               SIMD执行单元               │
│   num_warps         →     每block的warp数        控制并行度                  │
│   num_stages        →     流水线深度             控制软件流水线              │
│                                                                             │
│   关键映射规则：                                                              │
│   • tl.program_id(0) 获取当前block在grid中的索引                              │
│   • 每个block在独立的SM上执行，block间可并行                                   │
│   • block内的warp通过共享内存通信，需要__syncthreads()同步                    │
│   • Triton自动处理线程分配，开发者只需关注block级别的逻辑                       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**Q: 如何使用@triton.jit装饰器？线程配置（num_warps, num_ctas）如何设置？**

```python
import triton
import triton.language as tl

@triton.jit
def my_kernel(
    x_ptr,                    # 输入指针
    y_ptr,                    # 输出指针
    n_elements,               # 元素数量
    BLOCK_SIZE: tl.constexpr, # 编译时常量
):
    pid = tl.program_id(axis=0)
    block_start = pid * BLOCK_SIZE
    offsets = block_start + tl.arange(0, BLOCK_SIZE)
    mask = offsets < n_elements
    x = tl.load(x_ptr + offsets, mask=mask)
    y = x * 2
    tl.store(y_ptr + offsets, y, mask=mask)

def launch_kernel(x):
    y = torch.empty_like(x)
    grid = lambda meta: (triton.cdiv(x.numel(), meta['BLOCK_SIZE']),)
    my_kernel[grid](
        x, y, x.numel(),
        BLOCK_SIZE=1024,
        num_warps=4,      # 每block 4个warp = 128线程
        num_stages=2,     # 流水线深度
    )
    return y
```

| 参数 | 说明 | 推荐值 |
|-----|------|-------|
| **num_warps** | 每block的warp数（1warp=32线程） | 2/4/8/16，默认4 |
| **num_stages** | 软件流水线深度 | 2-4，内存密集型可更高 |
| **BLOCK_SIZE** | 每block处理的元素数 | 通常是1024或2048 |
| **num_ctas** | 每block的CTA数（多CTA较少用） | 默认1 |

**Q: Triton如何处理动态Shape？@triton.heuristics的作用是什么？**

```python
@triton.heuristics({
    'BLOCK_SIZE': lambda args: 1024 if args['n_elements'] > 4096 else 256,
})
@triton.jit
def adaptive_kernel(x_ptr, y_ptr, n_elements, BLOCK_SIZE: tl.constexpr):
    ...

@triton.autotune(
    configs=[
        triton.Config({'BLOCK_SIZE': 256}, num_warps=2),
        triton.Config({'BLOCK_SIZE': 1024}, num_warps=4),
        triton.Config({'BLOCK_SIZE': 4096}, num_warps=8),
    ],
    key=['n_elements'],
)
@triton.jit
def autotuned_kernel(x_ptr, y_ptr, n_elements, BLOCK_SIZE: tl.constexpr):
    ...
```

| 机制 | 作用 | 使用场景 |
|-----|------|---------|
| **@triton.heuristics** | 根据输入参数动态推导配置 | 已知规律的shape适配 |
| **@triton.autotune** | 自动搜索最优配置 | 性能敏感场景 |
| **key参数** | 指定影响配置的参数 | 缓存编译结果 |


**Q: 如何编写高性能Triton代码？内存访问优化有哪些技巧？**

| 优化技巧 | 说明 | 实现方法 |
|---------|------|---------|
| **合并访问** | 相邻线程访问相邻内存 | 使用tl.arange生成连续偏移 |
| **向量化加载** | 一次加载多个元素 | BLOCK_SIZE对齐到128字节 |
| **共享内存复用** | 减少全局内存访问 | 多阶段流水线(num_stages) |
| **避免bank conflict** | 共享内存访问优化 | 编译器自动处理 |
| **Tensor Core利用** | 使用dot操作 | tl.dot(a, b)自动映射 |

```python
def pipelined_kernel(

    pid_n = tl.program_id(1)

        # 流水线：当前块计算时，下一块预加载
```

**Q: Triton kernel的标准实现模式是什么？**

```python
import triton
import triton.language as tl
from flag_gems.utils import libentry

@libentry()
@triton.jit
def log10_kernel(
    x_ptr, y_ptr, n_elements,
    BLOCK_SIZE: tl.constexpr,
):
    pid = tl.program_id(axis=0)
    block_start = pid * BLOCK_SIZE
    offsets = block_start + tl.arange(0, BLOCK_SIZE)
    mask = offsets < n_elements
    
    x = tl.load(x_ptr + offsets, mask=mask)
    # log10(x) = log(x) / log(10)
    y = tl.log(x) / 2.302585092994046  # ln(10)
    tl.store(y_ptr + offsets, y, mask=mask)

def log10(x: torch.Tensor) -> torch.Tensor:
    y = torch.empty_like(x)
    grid = lambda meta: (triton.cdiv(x.numel(), meta['BLOCK_SIZE']),)
    log10_kernel[grid](x, y, x.numel(), BLOCK_SIZE=1024)
    return y
```

**Q: wrapper函数需要哪些参数校验？**

```python
def log10(x: torch.Tensor) -> torch.Tensor:
    # 1. 设备校验
    if not x.is_cuda:
        raise RuntimeError(f"Expected CUDA tensor, got {x.device}")
    
    # 2. 数据类型校验
    if x.dtype not in (torch.float16, torch.float32, torch.bfloat16):
        raise RuntimeError(f"Unsupported dtype: {x.dtype}")
    
    # 3. 非空校验
    if x.numel() == 0:
        return torch.empty_like(x)
    
    # 4. 执行kernel
    y = torch.empty_like(x)
    grid = lambda meta: (triton.cdiv(x.numel(), meta['BLOCK_SIZE']),)
    log10_kernel[grid](x, y, x.numel(), BLOCK_SIZE=1024)
    return y
```

```python
    for _ in range(100):
        flag_gems.log10(x)
    torch.cuda.synchronize()
    gems_time = (time.time() - start) / 100
    
    speedup = torch_time / gems_time
    print(f"PyTorch: {torch_time*1000:.3f}ms")
    print(f"FlagGems: {gems_time*1000:.3f}ms")
    print(f"Speedup: {speedup:.2f}x")
    
    assert speedup >= 0.9, f"Speedup {speedup:.2f} < 0.9"
```
